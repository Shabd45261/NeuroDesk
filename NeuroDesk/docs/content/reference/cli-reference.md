Complete reference for all NeuroDesk command-line interface (CLI) parameters and environment variables.

> **Note:** All CLI flags can also be set via environment variables. Environment variables take precedence over CLI flags. See [.env files]({{%relref "advanced/advanced-usage#env-files" %}}) for configuration file support.

## Global Flags

| Parameter | Default | Description | Environment Variable |
|-----------|---------|-------------|----------------------|
| `-h, --help` | | Show context-sensitive help | |
| `--log-level` | `info` | Set the level of logs to output [error,warn,info,debug,trace] | `$NEURODESK_LOG_LEVEL` |
| `--debug` | `false` | **DEPRECATED** - Use `--log-level=debug` instead. Enable debug logging | `$NEURODESK_DEBUG`, `$DEBUG` |

## Storage Flags

| Parameter | Default | Description | Environment Variable |
|-----------|---------|-------------|----------------------|
| `--models-path` | `BASEPATH/models` | Path containing models used for inferencing | `$NEURODESK_MODELS_PATH`, `$MODELS_PATH` |
| `--data-path` | `BASEPATH/data` | Path for persistent data (collectiondb, agent state, tasks, jobs). Separates mutable data from configuration | `$NEURODESK_DATA_PATH` |
| `--generated-content-path` | `TMPDIR/neurodesk-UID/generated/content` | Location for assets generated by backends (e.g. stablediffusion, images, audio, videos). Defaults under the OS temp dir (`$TMPDIR`, falling back to `/tmp`), scoped to the current user's UID so accounts sharing a host never collide. | `$NEURODESK_GENERATED_CONTENT_PATH`, `$GENERATED_CONTENT_PATH` |
| `--upload-path` | `TMPDIR/neurodesk-UID/upload` | Path to store uploads from files API. Defaults under the OS temp dir (`$TMPDIR`, falling back to `/tmp`), scoped to the current user's UID. | `$NEURODESK_UPLOAD_PATH`, `$UPLOAD_PATH` |
| `--neurodesk-config-dir` | `BASEPATH/configuration` | Directory for dynamic loading of certain configuration files (currently runtime_settings.json, api_keys.json, and external_backends.json). See [Runtime Settings]({{%relref "features/runtime-settings" %}}) for web-based configuration. | `$NEURODESK_CONFIG_DIR` |
| `--neurodesk-config-dir-poll-interval` | | Time duration to poll the NeuroDesk Config Dir if your system has broken fsnotify events (example: `1m`) | `$NEURODESK_CONFIG_DIR_POLL_INTERVAL` |

| `--models-config-file` | | YAML file containing a list of model backend configs (alias: `--config-file`) | `$NEURODESK_MODELS_CONFIG_FILE`, `$CONFIG_FILE` |
| `--artifact-download-concurrency` | `1` | How many files of a model artifact to download at once. `1` downloads sequentially. Raising it helps artifacts split into many files on a fast link, at the cost of more concurrent load on the models volume. Whole files only — a single file is never split, so resume and per-file checksum verification are unaffected | `$NEURODESK_ARTIFACT_DOWNLOAD_CONCURRENCY` |

Backend processes receive a private scratch directory through `TMPDIR`, `TMP`,
and `TEMP`. NeuroDesk removes that directory when the backend exits and removes
abandoned directories left by a NeuroDesk crash before starting another backend.
Set `$NEURODESK_BACKEND_TEMP_DIR` to choose their base volume. NeuroDesk always
appends `neurodesk-UID/backend-runtime`; the default base is `TMPDIR`.

## Backend Flags

| Parameter | Default | Description | Environment Variable |
|-----------|---------|-------------|----------------------|
| `--backends-path` | `BASEPATH/backends` | Path containing backends used for inferencing | `$NEURODESK_BACKENDS_PATH`, `$BACKENDS_PATH` |
| `--backends-system-path` | `/var/lib/neurodesk/backends` | Path containing system backends used for inferencing | `$NEURODESK_BACKENDS_SYSTEM_PATH`, `$BACKEND_SYSTEM_PATH` |
| `--external-backends` | | A list of external backends to load from gallery on boot | `$NEURODESK_EXTERNAL_BACKENDS`, `$EXTERNAL_BACKENDS` |
| `--external-grpc-backends` | | A list of external gRPC backends (format: `BACKEND_NAME:URI`) | `$NEURODESK_EXTERNAL_GRPC_BACKENDS`, `$EXTERNAL_GRPC_BACKENDS` |
| `--backend-galleries` | | JSON list of backend galleries | `$NEURODESK_BACKEND_GALLERIES`, `$BACKEND_GALLERIES` |
| `--autoload-backend-galleries` | `true` | Automatically load backend galleries on startup | `$NEURODESK_AUTOLOAD_BACKEND_GALLERIES`, `$AUTOLOAD_BACKEND_GALLERIES` |
| `--max-active-backends` | `0` | Maximum number of active backends (loaded models). When exceeded, the least recently used model is evicted. Set to `0` for unlimited, `1` for single-backend mode | `$NEURODESK_MAX_ACTIVE_BACKENDS`, `$MAX_ACTIVE_BACKENDS` |
| `--single-active-backend` | `false` | **DEPRECATED** - Use `--max-active-backends=1` instead. Allow only one backend to be run at a time | `$NEURODESK_SINGLE_ACTIVE_BACKEND`, `$SINGLE_ACTIVE_BACKEND` |
| `--preload-backend-only` | `false` | Do not launch the API services, only the preloaded models/backends are started (useful for multi-node setups) | `$NEURODESK_PRELOAD_BACKEND_ONLY`, `$PRELOAD_BACKEND_ONLY` |
| `--enable-watchdog-idle` | `false` | Enable watchdog for stopping backends that are idle longer than the watchdog-idle-timeout | `$NEURODESK_WATCHDOG_IDLE`, `$WATCHDOG_IDLE` |
| `--watchdog-idle-timeout` | `15m` | Threshold beyond which an idle backend should be stopped | `$NEURODESK_WATCHDOG_IDLE_TIMEOUT`, `$WATCHDOG_IDLE_TIMEOUT` |
| `--enable-watchdog-busy` | `false` | Enable watchdog for stopping backends that are busy longer than the watchdog-busy-timeout | `$NEURODESK_WATCHDOG_BUSY`, `$WATCHDOG_BUSY` |
| `--watchdog-busy-timeout` | `5m` | Threshold beyond which a busy backend should be stopped | `$NEURODESK_WATCHDOG_BUSY_TIMEOUT`, `$WATCHDOG_BUSY_TIMEOUT` |
| `--watchdog-interval` | `500ms` | Interval between watchdog checks (e.g., `500ms`, `5s`, `1m`) | `$NEURODESK_WATCHDOG_INTERVAL`, `$WATCHDOG_INTERVAL` |
| `--force-eviction-when-busy` | `false` | Force eviction even when models have active API calls (default: false for safety). **Warning:** Enabling this can interrupt active requests | `$NEURODESK_FORCE_EVICTION_WHEN_BUSY`, `$FORCE_EVICTION_WHEN_BUSY` |
| `--lru-eviction-max-retries` | `30` | Maximum number of retries when waiting for busy models to become idle before eviction | `$NEURODESK_LRU_EVICTION_MAX_RETRIES`, `$LRU_EVICTION_MAX_RETRIES` |
| `--lru-eviction-retry-interval` | `1s` | Interval between retries when waiting for busy models to become idle (e.g., `1s`, `2s`) | `$NEURODESK_LRU_EVICTION_RETRY_INTERVAL`, `$LRU_EVICTION_RETRY_INTERVAL` |
| `--model-load-failure-cooldown` | `10s` | After a model load fails, refuse new load attempts for that model for this long (HTTP 503 + `Retry-After`) so a client polling a broken model doesn't respawn a crashing backend every request. Doubles per consecutive failure up to 5m; reset on success. `0` disables | `$NEURODESK_MODEL_LOAD_FAILURE_COOLDOWN`, `$MODEL_LOAD_FAILURE_COOLDOWN` |

For more information on VRAM management, see [VRAM and Memory Management]({{%relref "advanced/vram-management" %}}).

## Chat Flags

Use `neurodesk chat` to run the built-in terminal agent against a NeuroDesk server.
The agent can run shell commands, delegate to sub-agents, and use MCP tools. Read-only
calls run on their own; everything else goes through an approval prompt you answer.
See [Terminal agent]({{% relref "features/terminal-agent" %}}) for the full feature page.

| Parameter | Default | Description | Environment Variable |
|-----------|---------|-------------|----------------------|
| `--endpoint` | `http://127.0.0.1:8080` | NeuroDesk server endpoint. The `/v1` path is added automatically when omitted. | `$NEURODESK_CHAT_ENDPOINT` |
| `--model` | | Model to use. Defaults to the only model the server offers, or asks when there are several. | |
| `--api-key` | | API key to use when the NeuroDesk server requires authentication. | `$NEURODESK_API_KEY`, `$API_KEY` |
| `--config-dir` | `~/.config/neurodesk/chat` | Directory holding the agent's config, plugins, and skills. | `$NEURODESK_CHAT_CONFIG_DIR` |
| `--trace-dir` | | Write a session LLM trace (NDJSON) to this directory. | `$NEURODESK_CHAT_TRACE_DIR` |
| `--cli` | `false` | Plain CLI mode instead of the full-screen interface. Pipe stdin for one-shot use. | |
| `--tui` | `false` | Force the full-screen interface. | |
| `--height` | | Run as an inline drop-down of this height, e.g. `40%`. | |
| `--tmux` / `--no-tmux` | | Control the tmux split. | |
| `--init` | | Print the shell integration script for `Ctrl+Space` (zsh, bash, or fish). | |
| `--yolo` | `false` | Auto-approve every tool call. Use with care. | `$NEURODESK_CHAT_YOLO` |

The agent's own subcommands are reached by passing them through. NeuroDesk's flags
must come first, because everything after the first positional argument is
forwarded verbatim:

```bash
neurodesk chat plugin install https://github.com/user/plugin
neurodesk chat skill list
neurodesk chat mcp add my-server -- npx -y @modelcontextprotocol/server-filesystem /tmp
neurodesk chat --config-dir /srv/agent plugin list   # flags first
```

{{% notice warning %}}
In a script, pass `--yes` to those subcommands. Without it, a non-interactive
`plugin install` installs the plugin, leaves it disabled, and still exits `0`.
{{% /notice %}}

Summon the agent from any shell prompt with `Ctrl+Space`:

```bash
echo 'eval "$(neurodesk chat --init zsh)"' >> ~/.zshrc
```

Inside a session:
- `/models` lists the models the server offers, marking the current one.
- `/model <name>` switches model, keeping the conversation.
- `/compact` summarizes the conversation so far to free up context.
- `/skill <name>`, `/agent <name> <task>`, `/attach <file>`, `/goal <text>`.

If no server is reachable, the agent offers to start one for the session
(interactive terminals only) and otherwise points you at `neurodesk run`.

Piped use needs `--cli`, and exits `0` when it answers:

```bash
echo "what is 2+2" | neurodesk chat --cli
```

Read-only tools still run in a piped session. A tool call that is not read-only has
nobody to approve it, so it is denied and the session exits `3`, a code chosen to be
distinct from the `1` a failure reports.

## Other Commands

NeuroDesk supports several subcommands beyond `run`:

- `neurodesk models` - Manage NeuroDesk models and definitions
- `neurodesk backends` - Manage NeuroDesk backends and definitions
- `neurodesk chat` - Run the built-in terminal agent against a NeuroDesk server
- `neurodesk tts` - Convert text to speech
- `neurodesk sound-generation` - Generate audio files from text or audio
- `neurodesk transcript` - Convert audio to text
- `neurodesk agent` - Run agents standalone without the full NeuroDesk server
- `neurodesk mcp-server` - Run the NeuroDesk admin tool surface as a stdio MCP server (controls a remote NeuroDesk instance over HTTP)
- `neurodesk worker` - Start a worker for distributed mode (generic, backend-agnostic)
- `neurodesk p2p-worker` - Run workers to distribute workload via p2p (llama.cpp-only)
- `neurodesk agent-worker` - Start an agent worker for distributed mode (executes agent chats via NATS)
- `neurodesk util` - Utility commands
- `neurodesk explorer` - Run P2P explorer
- `neurodesk federated` - Run NeuroDesk in federated mode
- `neurodesk completion` - Generate shell completion scripts for bash, zsh, or fish

Use `neurodesk <command> --help` for more information on each command.

## Examples

### Basic Usage

```bash
./neurodesk run

./neurodesk run --models-path /path/to/models --address :9090

./neurodesk run --f16
```

### Environment Variables

```bash
export NEURODESK_MODELS_PATH=/path/to/models
export NEURODESK_ADDRESS=:9090
export NEURODESK_F16=true
./neurodesk run
```

### Advanced Configuration

```bash
./neurodesk run \
  --models model1.yaml model2.yaml \
  --enable-watchdog-idle \
  --watchdog-idle-timeout=10m \
  --p2p \
  --federated
```
